# 03. Встановлення фреймворку Nest.JS та базові налаштування для роботи 

## Встановлення та початок роботи

1. Встановлення Nest CLI:

  Відкрийте термінал та введіть наступну команду для встановлення Nest CLI глобально:
  ```
  npm i -g @nestjs/cli
  ```

  Після встановлення ви можете перевірити версію Nest CLI за допомогою команди:
  ```
  nest -v
  ```

2. Створення нового проекту:
  
  Перейдіть до каталогу, де ви хочете створити свій проект, та виконайте команду:
  ```
  nest new my-first-nest-app
  ```

  Nest CLI створить новий проект з базовою структурою та необхідними файлами.`

3. Запуск проекту:

  Перейдіть до каталогу з проектом:
  ```
  cd my-first-nest-app
  ```

  Запустіть проект за допомогою команди:
  ```
  npm run start
  ```

За замовчуванням, сервер запуститься на порту 3000. Ви можете відкрити браузер та перейти за адресою http://localhost:3000, щоб побачити результат.


4. Вбудовані засоби відлагодження:

  NestJS підтримує різні засоби відлагодження, такі як `console.log()` та інструменти розробника у браузері. Для більш комплексної відлагодження можна використовувати спеціальні інструменти, такі як Node.js Inspector.

## Основні файли та каталоги

- `src/`: Цей каталог містить основний код вашого додатку. Тут знаходяться всі модулі, контролери, сервіси та інші компоненти, які складають ваш додаток.
- `src/app.module.ts`: Це головний модуль вашого додатку. Він відповідає за організацію та конфігурацію інших модулів, контролерів та сервісів. Саме тут визначаються залежності між різними компонентами та імпортуються інші модулі.
- `src/app.controller.ts`: Це контролер за замовчуванням, який створюється разом із проектом. Контролери відповідають за обробку вхідних запитів та повернення відповіді клієнту. Зазвичай, кожен контролер відповідає за певний ресурс або функціональність додатку.
- `src/app.service.ts`: Це сервіс за замовчуванням, який також створюється разом із проектом. Сервіси містять бізнес-логіку вашого додатку. Вони можуть використовуватися контролерами для отримання даних, обробки запитів та виконання інших операцій.
- `package.json`: Цей файл містить інформацію про проект, його залежності та скрипти. Тут ви можете знайти список встановлених пакетів, версію NestJS та інші корисні дані.

## Взаємодія між файлами

- **Модулі**: Модулі є будівельними блоками NestJS додатку. Вони організовують компоненти додатку в логічні групи. Головний модуль (app.module.ts) імпортує інші модулі, які, в свою чергу, можуть імпортувати інші модулі, і так далі.
- **Контролери**: Контролери залежать від сервісів. Вони використовують сервіси для виконання бізнес-логіки та отримання даних. Контролери також можуть використовувати інші сервіси або модулі для виконання певних завдань.
- **Сервіси**: Сервіси можуть залежати від інших сервісів або модулів. Вони можуть використовувати інші сервіси для виконання певних операцій або отримувати дані з інших модулів.

## Приклад

Уявіть собі, що ви створюєте додаток для управління завданнями. У вас може бути модуль завдань (tasks.module.ts), який містить контролер завдань (tasks.controller.ts) та сервіс завдань (tasks.service.ts). Контролер завдань буде використовувати сервіс завдань для створення, отримання, оновлення та видалення завдань. Сервіс завдань, в свою чергу, може використовувати інші сервіси або модулі для роботи з базою даних або іншими ресурсами.

## Важливо розуміти

Кожен компонент NestJS (модуль, контролер, сервіс) має свою відповідальність та роль у додатку.
Компоненти можуть взаємодіяти між собою, щоб забезпечити функціональність додатку.
Правильна організація файлів та компонентів є важливою для підтримки та масштабування додатку.

## Архітектура Модуль - Контролер - Провайдер

NestJS використовує модульну архітектуру, де кожен компонент (контролер, сервіс, тощо) належить до певного модуля. Модуль - це своєрідний контейнер, який об'єднує логічно пов'язані компоненти.

1. Модуль (Module):

  - Організує компоненти додатку в логічні групи.
  - Визначає залежності між компонентами.
  - Імпортує інші модулі для використання їх компонентів.
  - Декларує контролери, сервіси та інші компоненти, які входять до його складу.

2. Контролер (Controller):

  - Обробляє вхідні HTTP-запити (зазвичай, URL-адреси).
  - Викликає відповідні методи сервісів для виконання бізнес-логіки.
  - Повертає результат клієнту у вигляді JSON, HTML або іншого формату.
  - Контролери відповідають за маршрутизацію та обробку запитів, але не містять безпосередньо бізнес-логіки.

3. Провайдер (Provider):

  - Містить бізнес-логіку додатку.
  - Сервіси (Services) є одним з видів провайдерів.
  - Може надавати інші сервіси, конфігурацію або значення для використання в інших компонентах.
  - Провайдери можуть залежати від інших провайдерів, створюючи ієрархію залежностей.

## Взаємодія між компонентами

1. **Запит**: Клієнт надсилає HTTP-запит на певну URL-адресу.
2. **Маршрутизація**: NestJS визначає, який контролер відповідає за обробку цього запиту, на основі URL-адреси та методу запиту (GET, POST, PUT, DELETE тощо).
3. **Контролер**: Контролер отримує запит та викликає відповідний метод сервісу для виконання бізнес-логіки.
4. **Сервіс**: Сервіс обробляє запит, отримує дані з бази даних або інших джерел, виконує необхідні операції та повертає результат контролеру.
5. **Відповідь**: Контролер отримує результат від сервісу та формує HTTP-відповідь для клієнта.
