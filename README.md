# Додаємо аутентифікацію та авторизацію

План проведення заняття:

## 01. Додаємо новий роут за допомогою вбудованих інструментів

Для створення процесу аутентифікації та авторизації нам потрібен окремий контролер, який буди приймати запити щодо майбутної моделі користувача, то ж логічно, що новий роут для цього контролеру буде мати назву `user`.

І а цьому етапі ми можемо скористуватись вбудованим інструментом фреймфорку `NestJS` для автоматичного створення нового блоку модуль-контролер-сервіс для цього випадку. Для цього потрібно виконати наступні команди:

```bash
nest g module user
nest g controller user
nest g service user
```

У результаті у нас змінеться структура папки `src` нашого проекту - у корні з'явиться нова папка `user`, в якої з'являться файли модуля, контролера та сервісу, а також зміниться зміст файлу `app.modules.ts`.

Тепер, фреймворк `NestJS` буде автоматично обробляти всі запити до цього нового роуту - `user`, залишилося додати логіку аутентифікації.

## 02. Додаємо обробку нових роутів

Для обробки запиту `GET /user` новий контролер вже має заглушку, що повертає строку формату JSON, таким чином ми можемо запустити аплікацію і впевнетись, що знов створений контролер працює. Але слід подивитись у майбутнє й спланувати декілька роутів, що будуть стосуватись обробки даних нашого користувача.

- `GET /user` - перевірка запиту до роуту
- `POST /user` - аутентифікація за логіном та паролем
- `PUT /user` - оновлення даних користувача, функціонал має бути закритим


### 02.1. Створюємо логіку входу за логіном та паролем

На цьому етапі у нас буде вбудований користувач, що "захардкожений" у тілі нашої аплікації, але в подальшому ми винесемо всі ці дії туди, куди потрібно - шляхом взаїмодії з базою даних.

Вся бізнес логіка обробки запитів, що приходять до контролеру, має бути реалізована в сервісах відповідного модуля, у нашому випадку це файл `src/user/user.service.ts`

Для перевірки функціоналу POST запитов до нашої аплікації ми будемо користуватися командою `curl` що є вбудованою до __Linux Terminal__ та __Windows Power Shell__:

```bash
curl -X POST http://localhost:3000/user -d "username=admin&password=admin123"
```

Перемога! Після вдалого логіну до нас повернувся об'єкт користувача, й тепер є кілька способів тримати його у пам'яті аплікації як аутентифікованого. Спробуємо застосувати технологію JWT - ЖСОН веб токен.

### 02.2. Додаємо до аплікації авторизованість через JWT

Після вдалої аутентифікації (коректного логіну) користувача ми маємо отримати веб токен, який буде використовуватись у всіх подальших HTTP запитах нашого користувача, відповідно наша аплікація повинна з цим коректно працювати. Для початку додамо необхідні залежності:

```bash
npm install --save @nestjs/jwt
```

Далі додамо функціональність веб токену до нашого головного модулю `app`, бо надалі ми будемо використовувати веб токен скрізь по аплікації:

```typescript
@Module({
  imports: [
    UserModule,
    JwtModule.register({
      global: true,
      secret: 'THERE SHOULD BE SOME TEXT FROM OUTSIDE',
      signOptions: { expiresIn: '3600s' },
    }),
  ]
})
```

Тепер перевіремо через ПОСТ запит, що наш токен було додано до об'єкту, що повертається після вдалого логіну. Замість голого об'єкту даних користувача у нас закодований блок, що тем не менш ці дані має у собі.
