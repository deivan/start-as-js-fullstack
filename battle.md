# Побудування функціоналу двобія у режимі реального часу

Інформацію щодо заявок на двобій, та запис самого двобію, що відбувається, будемо тримати у базі Redis. Це дозволить нам швидко отримувати інформацію про поточні двобої та їх учасників, а також забезпечить ефективне зберігання та обробку даних у режимі реального часу.

## 1. Заявка на двобій буде містити в собі наступний набір даних:

```typescript
interface DuelRequest {
  id: number; // Унікальний ідентифікатор заявки
  challengerId: number; // Ідентифікатор гравця, який створив заявку
  opponentId?: number; // Ідентифікатор гравця, який прийняв заявку (може бути відсутнім, якщо заявка ще не прийнята)
  status: 'pending' | 'accepted' | 'rejected'; // Статус заявки
  createdAt: Date; // Час створення заявки (timestamp)
  battleRoomId?: string; // Ідентифікатор кімнати для двобою (може бути відсутнім, якщо заявка ще не прийнята)
}
```

Гравець створює заявку на двобій, яка зберігається у Redis зі статусом "pending". Інші гравці можуть переглядати список відкритих заявок та приймати їх. Коли заявка приймається, її статус змінюється на "accepted", і створюється кімната для двобою.

Роути для роботи з заявками на двобій:
- `POST /duel-requests`: Створення нової заявки на двобій.
- `GET /duel-requests`: Отримання списку всіх відкритих заявок на двобій.
- `POST /duel-requests/:id/accept`: Прийняття заявки на двобій.

## 2. Двобій у режимі реального часу

Після прийняття заявки на двобій, створюється кімната для двобою як структура надих наступного формату:

```typescript
interface BattleRoom {
  id: string; // Унікальний ідентифікатор кімнати для двобою
  player1Id: number; // Ідентифікатор першого гравця
  player2Id: number; // Ідентифікатор другого гравця
  status: 'active' | 'finished'; // Статус двобою
  createdAt: Date; // Час створення кімнати (timestamp)
  player1moves: Move[]; // Масив ходів, зроблених у двобої першого гравця,
  player2moves: Move[]; // Масив ходів, зроблених у двобої другого гравця,
  winnerId?: number; // Ідентифікатор переможця (може бути відсутнім, якщо двобій ще не завершився)
}
``` 
Хід у двобої - то є вибір зони атаки та зони захисту для кожного гравця. Після вибіру кожним гравцем ходу, результат порівнюється на сервері та відбуваєтьс зміна стану здоров'я гравців. Якщо здоров'я одного з гравців досягає нуля, двобій завершується, і визначається переможець.

Структура даних для ходу у двобої може виглядати наступним чином:

```typescript
interface Move {
  playerId: number; // Ідентифікатор гравця, який зробив хід
  attackZone: 'head' | 'body' | 'legs'; // Зона атаки
  defenseZone: 'head' | 'body' | 'legs'; // Зона захисту
  health: number; // Поточний рівень здоров'я гравця на початок ходу
  strike: number; // Сила удару
}
```

Приклад ходу й оцінка його результату:
- **Гравець 1** вибирає атаку в зону "head" та захист у зону "body". Його поточний рівень здоров'я - 10, а сила удару - 3.
- **Гравець 2** вибирає атаку в зону "body" та захист у зону "body". Його поточний рівень здоров'я - 10, а сила удару - 3.
- **Результат**: Гравець 1 отримує удар у "body", що збігається з його захистом, тому він втрачає лише 1 одиницю здоров'я, бо вдалий захист погасив 2 одиниці удару. Гравець 2 отримує удар у "head", що не збігається з його захистом "body", тому він втрачає 3 одиниці здоров'я (10 - 3 = 7), бо пропустив удар.

Роути, що іикористовуються для роботи з двобоями:
- `POST /battles/:id/move`: Виконання ходу у двобої.
- `GET /battles/:id/status`: Отримання поточного стану двобою, включаючи інформацію про здоров'я гравців та останні ходи.

## 3. Взаємодія через WebSocket

WebSocket буде використовуватися для передачі інформації про поточний стан двобою в режимі реального часу. Коли гравець робить хід запитом на відповідний роут, сервер обробляє його та надсилає оновлення всім учасникам двобою через WebSocket.

Додатково, серверна сторона має слідкувати за часом, що відведено гравцю для здійснення ходу. Якщо гравець не робить хід протягом визначеного часу, сервер може автоматично виконати хід за нього, не встановивши зони удару та захисту.

Коли бій закінчено, сервер надсилає фінальний результат двобою всім учасникам через WebSocket, включаючи інформацію про переможця та статистику бою. Також оновлюється запис у Redis, щоб відобразити завершення двобою та визначення переможця.
