## Тема: Робота з валідацією в DTO

### Призначення валідації

Створення DTO (Data Transfer Object) у вигляді звичайних класів (TypeScript) лише допомагає з типізацією під час розробки (compile-time). Проте це не захищає сервер від отримання некоректних даних на етапі виконання (run-time). Наприклад, клієнт може надіслати рядок замість числа або взагалі пропустити обов'язкове поле. Для вирішення цієї проблеми у NestJS використовується потужний механізм валідації на рівні DTO за допомогою пайпів (Pipes).

### Встановлення необхідних пакетів

Для реалізації валідації NestJS використовує сторонні бібліотеки під капотом. Їх потрібно встановити:

```ts
npm install class-validator class-transformer
```

* `class-validator` — містить набір декораторів для перевірки даних (наприклад, чи є поле рядком, чи воно не порожнє тощо).
* `class-transformer` — відповідає за перетворення простих JavaScript-об'єктів (які приходять по мережі) на реальні екземпляри класів DTO.

### Глобальне підключення ValidationPipe

Щоб валідація працювала автоматично для всіх вхідних запитів, необхідно підключити вбудований `ValidationPipe` на рівні всього додатку. Це робиться у файлі `main.ts`.

Оновлений `main.ts`:

```ts
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  
  // Підключення глобального пайпа для валідації
  app.useGlobalPipes(new ValidationPipe());
  
  await app.listen(3000);
}
bootstrap();
```

### Застосування декораторів у DTO

Після підключення `ValidationPipe` необхідно додати декоратори з пакету `class-validator` до полів у DTO.

Оновлений `CreateProductDto`:

```ts
import { IsString, IsNumber, IsOptional, IsNotEmpty, Min } from 'class-validator';

export class CreateProductDto {
  @IsString()
  @IsNotEmpty()
  readonly title: string;

  @IsNumber()
  @Min(0)
  readonly price: number;

  @IsString()
  @IsOptional()
  readonly description?: string;
}
```

* `@IsString()`, `@IsNumber()` — перевіряють тип даних.
* `@IsNotEmpty()` — гарантує, що поле не буде передано порожнім.
* `@Min(0)` — перевіряє, щоб число було не менше нуля.
* `@IsOptional()` — вказує, що поле є необов'язковим. Якщо його немає в запиті, валідатор не видасть помилку.

#### Валідація для UpdateProductDto

При оновленні (`PATCH`) всі поля зазвичай є необов'язковими. Ми можемо додати декоратор `@IsOptional()` до кожного поля.

Оновлений `UpdateProductDto`:

```ts
import { IsString, IsNumber, IsOptional, Min } from 'class-validator';

export class UpdateProductDto {
  @IsString()
  @IsOptional()
  readonly title?: string;

  @IsNumber()
  @Min(0)
  @IsOptional()
  readonly price?: number;

  @IsString()
  @IsOptional()
  readonly description?: string;
}
```
*Зауваження: У NestJS є зручніший спосіб створення `UpdateDto` на основі `CreateDto` за допомогою `PartialType` (з `@nestjs/mapped-types` або `@nestjs/swagger`). Це автоматично робить усі поля необов'язковими, але зберігає їхні правила валідації з базового класу.*

### Розширені налаштування ValidationPipe

`ValidationPipe` приймає об'єкт конфігурації, який дозволяє значно покращити безпеку та зручність роботи з даними.

Додавання налаштувань у `main.ts`:

```ts
app.useGlobalPipes(new ValidationPipe({
  whitelist: true,
  forbidNonWhitelisted: true,
  transform: true,
}));
```

**Розбір параметрів:**

1. **`whitelist: true`** — автоматично видаляє з вхідного запиту (payload) всі властивості, які не описані в DTO (тобто не мають декораторів валідації). Це захищає від отримання зайвого "сміття" або спроб перезаписати закриті поля від клієнта.
2. **`forbidNonWhitelisted: true`** — працює в парі з `whitelist`. Замість того, щоб просто мовчки видаляти зайві поля, сервер викине помилку `400 Bad Request` і вкаже клієнту, що він надіслав недозволені дані.
3. **`transform: true`** — автоматично трансформує вхідні дані до потрібних типів, які вказані в DTO (наприклад, перетворює рядкові числа з JSON у тип `Number`, якщо в DTO вказано `price: number`). Також це перетворює звичайні об'єкти на екземпляри класів DTO.

### Механізм роботи валідації під капотом

1. Клієнт відправляє HTTP-запит з тілом (JSON).
2. Запит доходить до контролера, але перед виконанням методу проходить через `ValidationPipe`.
3. Пайп використовує `class-transformer`, щоб перетворити JSON на об'єкт класу `CreateProductDto`.
4. В роботу вступає `class-validator`, який перевіряє значення полів згідно з вказаними декораторами.
5. Якщо є помилки (наприклад, передано рядок замість числа), `ValidationPipe` перериває обробку запиту і автоматично повертає клієнту `400 Bad Request` зі списком помилок та повідомленнями.
6. Якщо валідація пройшла успішно, об'єкт передається далі в контролер і сервіс.

### Користувацькі повідомлення про помилки та розширена валідація

Декоратори з пакету `class-validator` за замовчуванням генерують повідомлення про помилки англійською мовою. Проте кожен декоратор приймає об'єкт параметрів, у якому можна передати властивість `message` для задання власного (користувацького) тексту помилки, який буде зрозумілим для клієнта.

Окрім базових перевірок типу, `class-validator` надає величезну кількість декораторів для специфічних сценаріїв. Розглянемо їх на прикладі комплексного DTO:

```ts
import { 
  IsString, 
  IsInt, 
  IsPositive, 
  Length, 
  IsArray, 
  IsEnum, 
  Matches, 
  IsUrl, 
  ArrayMinSize 
} from 'class-validator';

// Перелік для прикладу валідації Enum
export enum UserRole {
  ADMIN = 'admin',
  USER = 'user',
  GUEST = 'guest',
}

export class ExtendedValidationDto {
  // 1. Користувацькі повідомлення та валідація довжини
  @IsString({ message: 'Ім\'я користувача має бути текстом' })
  @Length(3, 20, { message: 'Довжина імені має бути від 3 до 20 символів' })
  readonly username: string;

  // 2. Валідація цілих та позитивних чисел
  @IsInt({ message: 'Вік має бути цілим числом (без дробів)' })
  @IsPositive({ message: 'Вік має бути більшим за нуль' })
  readonly age: number;

  // 3. Валідація масивів
  @IsArray({ message: 'Теги мають бути передані у вигляді масиву' })
  @IsString({ each: true, message: 'Кожен окремий тег у масиві має бути рядком' })
  @ArrayMinSize(1, { message: 'Масив тегів не може бути порожнім' })
  readonly tags: string[];

  // 4. Валідація переліків (Enums)
  @IsEnum(UserRole, { message: 'Передано недійсне значення ролі користувача' })
  readonly role: UserRole;

  // 5. Валідація за допомогою регулярних виразів (RegExp)
  // Приклад: мінімум 8 символів, хоча б одна велика літера та одна цифра
  @Matches(/^(?=.*[A-Z])(?=.*\d)[a-zA-Z\d]{8,}$/, { 
    message: 'Пароль занадто слабкий. Використовуйте мінімум 8 символів, велику літеру та цифру' 
  })
  readonly password: string;

  // 6. Валідація URL-адрес
  @IsUrl({}, { message: 'Передано некоректне посилання на веб-сайт' })
  readonly website: string;
}
```

#### Детальний опис використаних декораторів:

*   **Користувацьке повідомлення (`message`)**: Властивість, яка додається в об'єкт налаштувань будь-якого декоратора. Вона замінює стандартний текст помилки на той, який ви вкажете (наприклад, перекладений українською мовою).
*   **Довжина рядка (`@Length`, `@MinLength`, `@MaxLength`)**: Перевіряє кількість символів у рядку. `@Length(min, max)` дозволяє задати одразу нижню та верхню межу.
*   **Цілі числа (`@IsInt`)**: На відміну від `@IsNumber()`, який пропускає дробові числа (наприклад, `10.5`), цей декоратор гарантує, що передане число є цілим (наприклад, `10`).
*   **Позитивні числа (`@IsPositive`)**: Гарантує, що число є строго більшим за нуль. Корисно для валідації віку, ціни або кількості товару.
*   **Масиви (`@IsArray`)**: Перевіряє, чи є передане значення масивом. 
    * *Опція `each: true`*: Використовується всередині інших декораторів (наприклад, `@IsString({ each: true })`), щоб застосувати перевірку не до самого масиву, а до **кожного елемента** всередині нього.
*   **Переліки (`@IsEnum`)**: Перевіряє, чи відповідає передане значення одному з варіантів, заздалегідь визначених у TypeScript `enum`. Запобігає передачі довільних або невідомих статусів.
*   **Регулярні вирази (`@Matches`)**: Найгнучкіший інструмент для валідації складних форматів тексту. Ідеально підходить для перевірки складності паролів, специфічних форматів номерів телефонів або паспортних даних на основі RegExp-патерну.
*   **URL (`@IsUrl`)**: Автоматично перевіряє, чи є переданий рядок валідною веб-адресою (включаючи перевірку протоколів `http/https`).
