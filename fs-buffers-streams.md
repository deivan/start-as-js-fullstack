# Конспект лекції: Робота з файлами, буферами та потоками у Node.js

Ця лекція присвячена низькорівневим та високорівневим інструментам Node.js для обробки даних, взаємодії з файловою системою та оптимізації використання оперативної пам'яті.

---

## 1. Робота з файлами (Module `node:fs`)

Взаємодія з файловою системою в Node.js побудована на базі стандартів POSIX, але адаптована під асинхронну природу JavaScript. Основний модуль `fs` надає три способи роботи: синхронний, через колбеки та через проміси.

### Ключові концепції:

- **Дескриптори файлів (File Descriptors):** Це цілі числа, які операційна система присвоює відкритому файлу. Через дескриптор ми можемо читати або записувати дані в конкретне місце файлу, не завантажуючи його повністю.

- **Методи доступу:** - `fs.readFile` / `fs.writeFile`: Використовуються для роботи з файлом як з цілим об'єктом (зручно для малих файлів).
    - `fs.open`, `fs.read`, `fs.write`: Низькорівневі операції, що працюють через дескриптори.

- **Спостереження за файлами:** Можливість реагувати на зміни у файлі або директорії в реальному часі.

### Розбір прикладів:

* **`1-readFileSync.js`**: Демонструє синхронне читання файлу. Програма зупиняє виконання (блокує потік), доки файл не буде повністю прочитаний. Це допустимо лише в скриптах ініціалізації, але не в високонавантажених серверах.

* **`2-readFile.js`**: Використання асинхронного підходу з колбеками. Node.js ініціює читання та продовжує виконувати інший код, а після завершення операції викликає функцію зворотного виклику.

* **`3-async.js`**: Сучасний підхід з використанням `fs.promises` та `async/await`. Робить код візуально схожим на синхронний, зберігаючи переваги асинхронності.

* **`4-error.js`**: Важливість обробки помилок (наприклад, відсутність файлу або брак прав доступу), щоб запобігти падінню всього процесу Node.js.

* **`5-stats.js`**: Отримання метаданих файлу: розмір, дата створення, тип (файл чи директорія).

* **`6-watch.js`**: Використання `fs.watch` для відстеження змін. Лектор наголошує, що поведінка цього методу може відрізнятися на різних операційних системах (Windows, Linux, macOS).

## 2. Робота з буферами (Class `Buffer`)

Буфер — це область пам'яті за межами рушія V8 (Heap), яка використовується для зберігання сирих бінарних даних. Оскільки JavaScript спочатку не мав засобів для роботи з бінарними даними, Node.js ввів клас `Buffer`.

### Ключові концепції:
- **Фіксований розмір:** Після створення розмір буфера неможливо змінити.

- **Типи виділення пам'яті:**
    - `Buffer.alloc(size)`: Виділяє пам'ять і заповнює її нулями (безпечно).
    - `Buffer.allocUnsafe(size)`: Швидко виділяє пам'ять, але вона може містити старі "сміттєві" дані.

- **Кодування:** Буфери дозволяють легко перетворювати бінарні дані в рядки (UTF-8, Base64, Hex) і навпаки.



### Розбір прикладів:

* **`1-alloc.js`**: Різниця між безпечним та швидким виділенням пам'яті. Пояснюється, чому `allocUnsafe` потребує обережності.

* **`2-from.js`**: Створення буфера з існуючих даних (рядків, масивів).

* **`3-read.js`**: Як зчитувати конкретні байти з буфера та працювати з числовими значеннями різних форматів.

* **`4-slice.js`**: Створення "зрізу" буфера. Лектор звертає увагу на те, що `slice` не копіює дані, а створює нове "вікно" на ту саму область пам'яті. Зміна даних у зрізі змінить дані в оригіналі.

* **`5-concat.js`**: Об'єднання декількох маленьких буферів в один великий.

## 3. Робота з файловими потоками (Streams)

Стріми — це найефективніший спосіб обробки даних у Node.js. Замість того, щоб завантажувати файл розміром 2 ГБ у пам'ять (що призведе до помилки), ми читаємо його маленькими частинами (чанками).

### Ключові концепції:

- **Readable Stream:** Потік для читання (наприклад, файл на диску).

- **Writable Stream:** Потік для запису (наприклад, мережеве з'єднання або новий файл).

- **Метод `.pipe()`:** Механізм "з'єднання" потоків, де дані автоматично перетікають з джерела в місце призначення.

- **Backpressure (Зворотний тиск):** Ситуація, коли джерело читає дані швидше, ніж отримувач встигає їх записувати. Потоки в Node.js автоматично обробляють це, призупиняючи читання.



### Розбір прикладів:

* **`1-readable.js`**: Створення потоку для читання файлу. Події `data` (прийшов новий чанк) та `end` (файл закінчився).

* **`2-writable.js`**: Запис даних у файл частинами. Використання методу `write`.

* **`3-pipe.js`**: Найбільш лаконічний спосіб копіювання файлів або передачі даних. Показує, як дані з `Readable` автоматично спрямовуються у `Writable`.

* **`4-gzip.js`**: Демонстрація ланцюжка потоків (Chaining). Читання файлу -> Стиснення (zlib) -> Запис у файл.

* **`5-http.js`**: Потужний приклад віддачі файлу через HTTP-сервер. Замість читання файлу в пам'ять перед відправкою, сервер починає відправляти перші байти клієнту відразу, як тільки почав їх читати з диска.

### Посилання на файли: https://github.com/HowProgrammingWorks/Streams/tree/master/JavaScript

---

**Підсумок:** Для простих скриптів підходять `fs.promises`, але для продуктивних серверів, що працюють з великими обсягами даних, критично важливо використовувати **Буфери** для маніпуляцій та **Стріми** для передачі.
