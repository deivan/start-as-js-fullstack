## Тема: Введення та структура аплікації NestJS

### Огляд фреймворку

**NestJS** — це один із найпопулярніших фреймворків для розробки серверних додатків, який базується на TypeScript. Він дозволяє будувати масштабовані, ефективні та зручні сервери. 

### Встановлення та ініціалізація проєкту

Для початку роботи необхідно глобально встановити інтерфейс командного рядка Nest (Nest CLI).

Встановлення Nest CLI:
```ts
npm install -g @nestjs/cli
```

Перевірка встановленої версії:
```ts
nest --version
```

Створення нового проєкту:
```ts
nest new project_name
```
*Під час створення проєкту CLI запропонує вибрати пакетний менеджер (npm, yarn або pnpm).*

### Базова структура додатку

Після генерації проєкту створюється набір конфігураційних файлів та головна тека `src`:

* `tsconfig.json` / `tsconfig.build.json` — конфігурація компілятора TypeScript.
* `package.json` — список залежностей та метаінформація про проєкт (версія, автор, скрипти запуску).
* `nest-cli.json` — налаштування самого Nest CLI.
* `src/` — головна тека з вихідним кодом додатку.

**Основні файли в теці `src/`:**

* `app.controller.ts` — головний контролер додатку.
* `app.module.ts` — головний модуль, який об'єднує всі інші модулі (наприклад, модуль авторизації, модуль продуктів тощо).
* `app.service.ts` — сервіс, де розташовується базова бізнес-логіка.
* `main.ts` — точка входу в додаток. Тут створюється екземпляр додатку за допомогою `NestFactory.create()` та вказується порт для прослуховування.

### Запуск додатку

Для запуску проєкту в режимі розробки використовується команда:
```ts
yarn run start:dev 
// або
npm run start:dev
```
За замовчуванням бекенд запускається на порту 3000 (`http://localhost:3000`).

### Архітектура NestJS

Архітектура влаштована ефективно завдяки розділенню обов'язків. Головні будівельні блоки додатку — це модулі, контролери та сервіси.

**1. Модулі (Modules)**
Це контейнери, які групують компоненти для вирішення конкретної задачі. Наприклад, модуль для роботи з користувачами (`UsersModule`) включає в себе відповідний контролер та сервіс. Модулі не дозволяють коду перетворюватися на хаос.

**2. Контролери (Controllers)**
Компоненти, що приймають вхідні HTTP-запити від клієнта та передають їх на обробку сервісам. 
* *Важливо:* Контролери **не займаються** бізнес-логікою. Їхня єдина мета — прийняти запит (наприклад, GET-запит на отримання користувачів) і повернути клієнту готовий результат.

**3. Сервіси (Services)**
Це "мозок" додатку. Коли контролер отримує запит, він делегує роботу сервісу.
* Сервіси відповідають за бізнес-логіку: взаємодію з базою даних (через ORM), валідацію, перевірку даних, обробку помилок тощо.

**Життєвий цикл запиту в реальному додатку:**

1. Клієнт відправляє HTTP-запит (наприклад, запит на отримання списку користувачів).
2. Запит потрапляє до відповідного **Контролера**.
3. Контролер викликає метод у **Сервісі**.
4. Сервіс виконує свою роботу (наприклад, робить запит до БД і отримує масив користувачів).
5. Сервіс повертає дані Контролеру.
6. Контролер віддає результат назад клієнту.
