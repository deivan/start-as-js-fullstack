Практикум: Таймери, таймаути та EventEmitter у JavaScript та Node.js

## Синхронні та асинхронні колбеки

Для розуміння таймерів і подій важливо розрізняти синхронні та асинхронні колбеки (функції зворотного виклику):

Синхронний колбек: Функція виконується відразу в процесі обчислень, до того, як керування повернеться з основної функції.

Асинхронний колбек: Функція передається для виклику в майбутньому (наприклад, після завершення операції вводу/виводу або спрацьовування таймера). Вона не блокує основний потік виконання.

### Блокуючі затримки

Якщо зробити паузу за допомогою довгого циклу while (перевіряючи поточний час), то це заблокує потік. Під час такого очікування програма не зможе реагувати на жодні інші події (натискання клавіш, мережеві запити тощо), оскільки стек викликів буде зайнятий.
(Див. приклад у файлі 1-sleep.js)

### Асинхронні затримки (неблокуючі)

Щоб зробити паузу, не блокуючи потік, використовують асинхронні інструменти:

Використання Promise та setTimeout у поєднанні з async/await. Це дозволяє віддати керування в Event Loop на час очікування.
(Див. приклади у файлах 2-sleep-promise.js та 3-sleep-callback.js)

## Функції таймерів у Node.js

У Node.js (та браузерах) існують різні способи відкласти виконання коду:

setTimeout(callback, delay, [args...]) — викликає колбек не раніше, ніж через delay мілісекунд.

setInterval(callback, delay) — періодично викликає колбек з інтервалом delay.

setImmediate(callback) — (специфічно для Node.js) планує виконання колбеку на фазі "check" в Event Loop, відразу після завершення операцій вводу/виводу.

process.nextTick(callback) — (специфічно для Node.js) виконує колбек максимально швидко, до переходу до наступної фази Event Loop. Має найвищий пріоритет серед відкладених викликів.

(Демонстрація послідовності викликів: файл 4-order.js)

Порядок виконання (пріоритети) зазвичай такий:

Синхронний код.

process.nextTick.

setTimeout (навіть із нульовою затримкою).

setImmediate / колбеки читання файлів тощо.

Точність таймерів
Таймери в JS не є абсолютно точними. Вони гарантують лише те, що функція не викличеться раніше заданого часу. Затримка може бути більшою, якщо Event Loop зайнятий іншими ресурсоємними задачами (наприклад, збиранням сміття або важкими обчисленнями, як-от обчислення чисел Фібоначчі).
(Див. приклади вимірювання часу у файлах 5-precision.js та 6-fibonacci.js)

## Особливості таймерів у Node.js

Таймери в Node.js не є частиною специфікації мови JavaScript (як і в браузері, де їх надає сам браузер). У Node.js їх реалізує ядро.
setTimeout та setInterval повертають не просто числовий ідентифікатор (як у браузері), а повноцінний об'єкт таймера з багатьма властивостями та методами.

(Демонстрація об'єкта таймера: файл 7-timers.js)

### Методи unref() та ref()

Ці методи доступні лише у Node.js:

timer.unref() — дозволяє програмі завершити роботу, навіть якщо цей таймер ще працює (він перестає блокувати Event Loop).

timer.ref() — повертає таймеру здатність утримувати програму від завершення.

(Див. приклад: файл 8-unref.js)

Також у старих версіях існували високопродуктивні таймери (enroll/unenroll), але наразі вони визнані застарілими (deprecated). (Див. приклад: файл 9-enroll.js)

## Патерн EventEmitter

EventEmitter — це патерн (і вбудований клас у Node.js), який реалізує шину подій. Він дозволяє:

Генерувати іменовані події та передавати з ними дані (метод emit).

Підписуватися на ці події з інших частин програми (метод on).

Це використовується для слабкого зв'язування компонентів: відправник події може не знати, чи є хтось, хто її прослуховує.

### Використання вбудованого модуля events

Можна створити екземпляр класу EventEmitter та вішати обробники. На одну подію можна повісити багато обробників.
Також можна розширювати базовий EventEmitter, щоб, наприклад, перехоплювати всі події за допомогою спеціального імені події (наприклад, *).
(Див. файли: test.js та 4-star-fix.js)

### Кастомна реалізація EventEmitter

Лектор демонструє, що сутність EventEmitter можна легко написати самостійно різними способами (вони працюватимуть однаково):

На прототипах: Класична реалізація з конструктором, об'єктом для зберігання колекції подій та методами on і emit. (Див. приклад: 2-prototype.js)

На замиканнях (функціональний стиль): Стан (колекція подій) зберігається у замиканні функції, яка повертає об'єкт із методами. (Див. приклад: 6-closure.js та мінімізований варіант 7-closure-optimized.js)

### Розширена реалізація: Повноцінний клас, що містить методи:

on(name, fn) — підписка.

emit(name, ...data) — генерація події.

once(name, fn) — підписка, яка спрацьовує лише один раз (реалізується через функцію-обгортку).

remove(name, fn) — видалення конкретного обробника (потребує обережної роботи з обгортками від методу once).

clear(name) — видалення всіх обробників події.

count(name) — підрахунок кількості обробників.

listeners(name) — повертає копію масиву обробників (щоб уникнути мутацій ззовні).

names() — повертає всі імена подій.
(Див. повну реалізацію у файлі 8-enhanced.js та "продвинуту" оптимізацію на Map у файлі 10-map.js)

Порада від лектора: Не варто використовувати EventEmitter для абсолютно всіх асинхронних операцій у програмі. Для лінійного контролю потоку краще підходять колбеки або Promise/async-await. EventEmitter ідеальний саме для реакції на події.
