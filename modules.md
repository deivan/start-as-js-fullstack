# Конспект лекції: Node.js — Структура додатків, модулі, пакети та залежності

## 01. Експорт та імпорт (CommonJS)

У Node.js традиційно використовується система модулів CommonJS. Основний механізм обміну кодом між файлами базується на об'єктах module.exports та функції require.

### Експорт (`1-export.js`)

Для того, щоб зробити функції, класи або об'єкти доступними в інших модулях, ми присвоюємо їх властивостям module.exports.

Можна експортувати як окремий об'єкт, що містить кілька елементів.

Це дозволяє інкапсулювати логіку всередині файлу і відкривати лише необхідний інтерфейс.

### Імпорт (`2-require.js`)

Функція require використовується для підключення:

Вбудованих модулів Node.js (наприклад, fs, events, timers). Рекомендується використовувати префікс node:, наприклад: require('node:fs').

Сторонніх бібліотек з папки node_modules.

Власних локальних файлів за допомогою відносних шляхів (обов'язково починаються з ./ або ../).

## 02. Розширення та пошук модулів

Node.js має певний алгоритм пошуку файлів, коли ви викликаєте require:

Спочатку шукається файл з точною назвою.

Потім додаються розширення .js, .json, .node.

Якщо вказано шлях до директорії, Node.js шукає в ній файл index.js або звертається до поля main у package.json цієї директорії.

## 03. Кешування модулів (`3-resolve.js, 4-cache.js`)

Модулі в Node.js завантажуються лише один раз. Після першого виклику require результат кешується.

Наступні виклики require для того самого файлу повертатимуть об'єкт із кешу.

Це забезпечує ефективність, але вимагає розуміння того, що стан модуля (state) може зберігатися між різними частинами програми.

## 04. Патерн Singleton (`5-singleton.js`)

Завдяки кешуванню модулів, реалізація патерну Singleton стає природною для Node.js. Якщо модуль експортує екземпляр класу (через new), то всі інші модулі, які його імпортують, отримають посилання на один і той самий об'єкт.

## 05. Глобальні змінні та контекст (`6-global.js`)

Хоча в модулях можна створювати глобальні змінні через об'єкт global, це вважається поганою практикою (anti-pattern). Модулі мають бути ізольованими. Краще передавати залежності через аргументи або імпортувати їх.

## 06. Mixins — домішки (`7-mixin.js`)

Це підхід, що дозволяє додавати функціональність об'єкту або класу «на льоту», копіюючи методи з одного об'єкта в інший. Це альтернатива множинному успадкуванню, яке не підтримується в JavaScript.

## 07. Робота з пакетами та package.json

package.json: головний файл опису проекту. Містить назву, версію, точку входу (main), скрипти та список залежностей.

node_modules: папка, де зберігаються всі встановлені залежності.

package-lock.json: фіксує точні версії всіх встановлених пакетів та їхніх залежностей для забезпечення ідентичності середовища на різних машинах.

## 08. Сучасні ESM модулі (`8-export.mjs`, `9-import.mjs`)

Починаючи з пізніх версій Node.js, підтримується стандарт ECMAScript Modules (ESM):

Використовуються ключові слова export та import.

Файли зазвичай мають розширення .mjs або проект має "type": "module" у package.json.

ESM модулі є асинхронними та мають суворіший режим виконання.

## 09. Динамічний імпорт (`9-dynamic.js`, `10-dynamic.mjs`)

Функція import() (як вираз) дозволяє завантажувати модулі динамічно під час виконання коду. Це корисно для лінивого завантаження (lazy loading) або завантаження модулів на основі певних умов.
