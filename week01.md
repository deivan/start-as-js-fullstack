# Концепція та Архітектура Node.js

## Що таке Node.js?

Це середовище виконання (runtime) JavaScript на серверній стороні.

Дозволяє JS взаємодіяти з мережею, базами даних, файловою системою та операційною системою.

## З чого складається:

Рушій V8: Виконує JavaScript код (той самий рушій, що у Google Chrome). Він є замінним (можна використовувати ChakraCore, SpiderMonkey тощо), але V8 — стандарт.

Бібліотека Libuv: Забезпечує асинхронний неблокуючий ввід/вивід (Event Loop).

Має власний пул потоків (Thread Pool), за замовчуванням 4 потоки, для виконання системних операцій (робота з файлами, DNS, криптографія).

C++ Addons / N-API: Інтерфейси для взаємодії з низькорівневим кодом та бібліотеками (OpenSSL, zlib, http-parser).

Node.js API (Bindings): "Клей", що з'єднує JS-код із можливостями C++ та OS.


# Event Loop (Цикл подій)

## Принцип роботи:

Node.js використовує один потік для виконання JavaScript коду, але системні операції можуть виконуватися паралельно завдяки Libuv.

Callback Queue: Коли асинхронна операція завершується, її callback потрапляє в чергу. Event Loop забирає їх з черги та виконує у V8.

## Фази Event Loop (спрощено):

Timers: Виконання setTimeout, setInterval.

Pending Callbacks: Системні колбеки (наприклад, помилки TCP).

Poll: Отримання нових подій вводу/виводу (читання файлів, мережеві запити).

Check: Виконання setImmediate.

Close Callbacks: Закриття ресурсів (наприклад, socket.on('close')).

### Важливо: Не потрібно знати фази напам'ять для звичайної розробки, але важливо розуміти, що блокування Event Loop (довгими синхронними обчисленнями) зупиняє весь сервер.


# Модель масштабування

## Node.js vs Класична модель (Apache/Java/PHP old school):

Класична: Thread-per-request (Один потік на один запит). Велика витрата пам'яті та ресурсів на перемикання контексту процесора при тисячах підключень.

Node.js: Single Thread + Non-blocking I/O. Один потік обслуговує тисячі клієнтів. Поки один запит чекає на дані з БД, Node.js обробляє наступний.

Переваги:

Економія оперативної пам'яті.

Відсутність витрат на Context Switching.

Висока ефективність для I/O-bound задач (багато вводу/виводу, мало обчислень).


# Робота зі станом (Stateful vs Stateless)

У Node.js додаток живе довго (Long-living process), на відміну від PHP, де процес часто помирає після обробки запиту.

## Можливості:

Connection Pools: З'єднання з БД (Postgres, Redis) створюються один раз і перевикористовуються.

In-memory Caching: Можна кешувати дані прямо в оперативній пам'яті процесу (потребує обережності при масштабуванні).

## Ризики: Оскільки всі клієнти в одному процесі, витік пам'яті або падіння процесу впливає на всіх користувачів одночасно.


# Приклад створення HTTP сервера (Native)

Для створення сервера не обов'язково використовувати фреймворки (Express/Nest), достатньо вбудованих модулів:

## Модулі: node:http, node:fs, node:path.

## Безпека (Path Traversal): При віддачі статичних файлів обов'язково перевіряти, чи не намагається користувач вийти за межі дозволеної папки (наприклад, через ../).

## Streams (Потоки): Для ефективної віддачі файлів використовується fs.createReadStream().pipe(response). Це не завантажує весь файл у пам'ять, а передає його частинами.


# Екосистема та Інструменти

## Глобальні об'єкти:

global, process, Buffer.

__dirname, __filename (у CommonJS), module, require.

## Модульність:

CJS (CommonJS): require('fs') — старий стандарт.

ESM (ECMAScript Modules): import fs from 'node:fs' — сучасний стандарт. Рекомендується використовувати префікс node: для вбудованих модулів.

NPM (Node Package Manager):

Дозволяє керувати залежностями.

### Ризики: Supply Chain Attacks (вразливості у ланцюжку поставок). Потрібно перевіряти пакети (npm audit), мінімізувати кількість залежностей.


# Сфери застосування (Use Cases)

## Де Node.js підходить ідеально:

REST API та Backend для SPA (Single Page Applications).

Real-time додатки (чати, месенджери, ігри) через WebSockets.

Стрімінг мультимедіа.

BFF (Backend for Frontend) — "клей" між мікросервісами та клієнтом.

Інструменти розробки (CLI, бандлери).

## Де Node.js не підходить:

CPU-bound задачі: Важкі математичні обчислення, обробка відео, наукове моделювання (блокує Event Loop).

Системи жорсткого реального часу (Hard Real-time): Через Garbage Collection (зборку сміття) неможливо гарантувати точний час відгуку.


# Сучасний Node.js (Тренди та Фічі)

Актуальні версії (LTS) вже мають багато можливостей "з коробки", що зменшує потребу у сторонніх бібліотеках:

Fetch API: Вбудований fetch (як у браузері).

Test Runner: Вбудований модуль для тестів (node:test).

Worker Threads: Для розпаралелювання важких обчислень.

Web Crypto API & Web Streams: Сумісність із веб-стандартами.

Watch Mode: Запуск із прапорцем --watch для перезавантаження при змінах.


# Проблеми та Безпека

Спільний адресний простір: Всі користувачі знаходяться в одному контексті пам'яті. Помилка в коді може дати доступ до даних інших користувачів.

Залежності: Велика кількість дрібних NPM-пакетів збільшує ризик занесення шкідливого коду.

Якість коду: "Callback Hell" (вирішується Promises/Async-Await) та блокуючі операції в коді новачків.

Архітектура: Важливо дотримуватися принципів чистої архітектури (Dependency Injection, розділення шарів), щоб уникнути перетворення проекту на "велику кулю бруду".
